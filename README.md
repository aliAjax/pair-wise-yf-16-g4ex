# hxyfront-62004 滑雪板调校 · 季前复调工作台

面向滑雪板调校店换季复调场景：把**客户档案、维修工单、底板损伤、刃角配方**接成一张季前复调单。

## 核心业务规则

1. **四单合一 · 读取上次交付参数**：客户档案 → 雪板 → 复调单 → 刃角配方版本链；工单展示去年交付时锁定的手写配方与底板指纹。
2. **底板指纹决定配方能否沿用**（`src/domain.ts` `boardFingerprint`）：指纹由底板损伤（位置/长度/深度/程度/状态）与修补材料（类型/品牌）哈希得到。
   - 底刃更换、新增划痕、修补材料变化 → 指纹变化 → 去年手写配方与现底板不符、**沿用失效**；
   - 必须前台重新存配方（版本绑定当前指纹），技师**重算实测差值**后，打磨工序门禁才放行；
   - 存配方之后底板又变化，已确认的实测与差值一并作废。
3. **两名前台并发保存不丢单**：所有保存经服务端串行落盘——先落盘的一版为「原单依据」，后保存的一版进「待前台裁决」另列，**不能盖掉原单**；前台可采纳（原单降级为留档可溯）或放弃（维持原单）。
4. **断网与次日恢复**：断网期间动作进本地发件箱（localStorage 持久化，刷新/第二天仍在），本地用同一份纯归约器做乐观推断；上线后按 FIFO 带**幂等键**重放：
   - 成功动作从发件箱移除并同步服务端权威状态；
   - 被服务端门禁驳回的动作标为「服务端驳回」，由人工重试或丢弃；
   - 已确认步骤的重试幂等，`confirmedAt` 等状态不被第二次执行改写（测试覆盖）。
5. **工序门禁**：六道工序（复检 → 实测重算 → 打磨 → 修补 → 打蜡 → 终检）强制顺序；打磨前置条件为「配方与当前指纹一致 + 实测差值已确认」。

## 目录

```
src/
  types.ts           领域模型与动作
  domain.ts          底板指纹、配方失效判定、差值重算、门禁、纯归约 reducer
  server.ts          模拟车间服务器（localStorage 持久化 + 幂等键缓存 + 在线/断网）
  store.ts           客户端发件箱（离线暂存 / FIFO 重放 / 次日恢复 / 驳回处理）
  seed.ts            三个演示客户（底板已换底刃 / 指纹一致可沿用 / 双前台并发）
  components/        工单列表、工单详情、连通性发件箱栏
  domain.test.ts     领域规则单测（8）
  store.test.ts      端到端集成测试（4）
```

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62004
npm test           # 12 个测试：指纹失效 / 并发裁决 / 断网次日重放
npm run build      # tsc 类型检查 + 生产构建
```

## 页面上怎么演

- **RT-2601（陈凯）**：已换底刃 + 新划痕，旧配方直接判失效；可在「底板损伤」里再登记一道划痕观察指纹再次变化。
- **RT-2603（李然）**：点「⚡ 演示：两名前台同一时刻保存」，v1 成为原单依据、v2 进待裁决，裁决后 v1 留档。
- 顶栏「模拟断网」后确认实测/工序，动作进入发件箱；点「⏭ 第二天开机上线」，复调单从持久化恢复并重放未确认步骤，驳回项会单独标出。
